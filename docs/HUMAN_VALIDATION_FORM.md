# Human validation form — concept relationship review (superseded)

> **Superseded by [`SEMANTIC_HUMAN_VALIDATION_FORM.md`](SEMANTIC_HUMAN_VALIDATION_FORM.md)** (2026-10-02): the form now
> collects only a Reviewer ID, uses choices A–H and High / Moderate / Low confidence, and shows every evidence line
> verbatim. This page describes the earlier layout, which `import-form` still accepts.

This is the exact content of the Google Form generated by `scripts/evaluation/create_semantic_validation_form.gs` for package `semantic_gold/computer-science-and-engineering/v1`. It contains 48 cases, a stratified subset of the frozen 88-case benchmark.

The form never shows any of the following:
- a model prediction;
- the assistant's adjudication;
- the deterministic rule's answer;
- a confidence score from any system;
- an expected answer.

## How to create the form

1. Open [script.google.com](https://script.google.com) and choose **New project**.
2. Paste `scripts/evaluation/create_semantic_validation_form.gs` into the editor.
3. Run `createSemanticValidationForm` and authorise it. The form's URL and its edit URL are written to the log.
4. Send the form URL to each of the two reviewers separately. Do not share responses between them.
5. When both have finished, open **Responses**, choose **Link to Sheets**, and download the sheet as CSV.
6. Import the responses:

```
python3 scripts/evaluation/semantic_validation.py import-form --package data/evaluation/semantic_gold/computer-science-and-engineering/v1/ --csv responses.csv
```

An import-ready alternative without Google Forms is `data/evaluation/semantic_gold/computer-science-and-engineering/v1/blind_export.csv`. The reviewer fills in the `relationship`, `confidence_1_to_5` and `rationale` columns, and it is imported with `import-sheet`.

- Reviewer ID (name or pseudonym)

- Relevant experience (years)

## Section 2 — How to judge

For each case, read Concept A with its context and Concept B with its description, then choose how **A relates to B**:

| Choice | Meaning |
|---|---|
| Equivalent concept | A and B denote the same thing in this context |
| A is broader | A is a broader concept that includes B |
| A is more specific | A is a narrower concept, a kind or part of B |
| Related concept | clearly connected, but neither equal nor one inside the other |
| Partial overlap | they share part of their meaning |
| Unrelated | different things (e.g. a shared word with a different sense) |
| Ambiguous | the context allows more than one reading |
| Not enough evidence | the context does not decide it |

A shared word, or one phrase appearing inside another, is not enough for *Equivalent concept* or for a hierarchy. Confidence is scored from 1 (guess) to 5 (certain).
